# fw-todo-2

訓練で作成した、1人用のToDo管理アプリです。配布仕様に、利用者の希望で機能とデザインを追加しています。

## できること

- 登録・確認・編集・検索・期限順の並び替え
- 未完了を初期表示、完了への切り替え、期限切れと高優先度の目印
- 一覧の10件ごとのページ分け、削除済み項目の表示・復元、CSV出力
- 月・週カレンダー、祝日、東京・神奈川の代表地点の天気マーク
- ファイル添付・ダウンロード・削除
- 初回ユーザー設定とログイン・ログアウト
- MCP（AIから使う窓口）の8つの道具

画面は淡い紫と緑、丸い書体で統一しています。

## 起動方法

Docker Desktopを起動し、このフォルダーで次を実行します。DB（データの保存先）はMySQL 8.0、アプリはJava 21・Spring Bootを使用します。Dockerで起動する場合、PC側へのJavaのインストールは不要です。

1. プロジェクト直下に `.env` を用意し、`MYSQL_ROOT_PASSWORD=自分で決めたDB用パスワード` を設定します。既存環境では元の値を使い続けてください。これはアプリのログインパスワードとは別です。
2. 次のコマンドで起動します。

```powershell
docker compose up -d --build
```

3. [TOP](http://localhost:8081/) または [一覧](http://localhost:8081/todos) を開きます。起動完了まで少し時間がかかる場合があります。

停止は `docker compose stop`、状態確認は `docker compose ps`、動作記録の確認は `docker compose logs app` です。

DBへのPC側の接続ポートは3307、アプリは8081です。`.env` と添付ファイルはGitへ登録しません。実際のパスワードを提出資料に書かないでください。

## 初回ログイン設定

- ユーザーが未登録なら初回設定へ案内されます。ユーザー名とパスワードを自分で決めます。既定のログイン情報はありません。
- ユーザー名は空白なし・50文字以内、パスワードは8文字以上かつUTF-8で72バイト以内で、確認用の入力と一致する必要があります。
- 設定後はログイン画面を使います。初回設定で既存アカウントを上書きすることはできません。
- パスワードはハッシュ化（元に戻せない形への変換）して保存します。専用の変更・再設定画面は現在ありません。
- 最終授業でログインの追加が認められたため、自主的な追加機能として実装しています。

## データの保存と初期化

- DBはDockerの `fw-db-data`、添付ファイル本体は `fw-upload-data` というボリューム（コンテナーを作り直しても残る保存領域）を使います。実際の名前にはプロジェクト名が付きます。
- `initdb/*.sql` は、DBの保存領域が初めて作られたときだけ実行されます。既存DBに対して、SQLファイルを直しただけで列やテーブルが追加されるわけではありません。
- 現在のSQLはテーブルの作成用です。初期のやること5件やテスト用15件を自動投入するものではありません。
- データを残す場合はボリュームを削除しないでください。機能追加前のDBを使う場合は、DB設計書の現在の構造と照合し、データを維持して変更する必要があります。

## API・AIからの利用

- `/api/todos`、`/api/todos.csv`、`/api/holidays`、`/api/weather` はログインが必要です。APIの変更操作にはCSRF対策（意図しない送信を防ぐ仕組み）の確認情報も必要です。
- MCPの接続先は `http://localhost:8081/mcp`。MCPの認証は今回保留しているため、画面のログインとは別の扱いです。
- 外部へのデータ取得はアプリ側が行います。祝日はHolidays JP、天気はOpen-Meteoを使います。予報範囲外・通信失敗時は天気が出ません。
- 添付は1回1ファイル・10MBまで。許可する種類と操作は画面設計書を参照してください。
